## 判断依据与边界

资格状态由职位条件原文、可识别的学历 / 学位层级、专业名称 / 代码和个人档案中对应学历阶段的专业等因素计算。判断包括专业、学历、学位、政治面貌、毕业身份、基层工作经历、服务基层项目和特殊备注。“与最高学历相对应的学位”按符合处理；若备注是唯一待核验项，综合状态为初步符合，逐项判断仍明确提示核对备注。其他资料缺失或条件待核验会继续反映在资格状态中。系统输出不是招录机关的资格审查结论。

工作地点只按职位表“工作地点”字段解析。省级解析率为 100%；无法从原文识别的地区保留原文并待核，不从部门所在地反推。详情保留工作簿全部 27 项字段，空备注与其他空单元格仍如实留空。完整分省职位数和招录数见 [`2027_data_audit.md`](../../research/national/2027_data_audit.md)。

## 对最终交付问题的回答

1. **原京考是否完整保留？** 原页面路由、职位及学习模块没有被重写；加入导航和可选工作区字段。基线测试在本次改动前 96/96 通过；最终全套测试结果见下节。既有未提交工作树改动保留。人工浏览器回归受本机 HTTP 预览的沙箱权限阻止，未声称完成人工视觉验收。
2. **国考职位是否全部导入？** 本机源工作簿的四个数据表全部读取并逐条比较；没有与官方附件逐字节对照。
3. **职位 / 招录人数？** 19,426 个职位、35,691 人。
4. **专业匹配如何工作？** 资格判断结合明确专业代码与名称；公共管理快捷筛选按职位表专业原文中管理学类、公共管理、土地资源管理等文字或 `12` 开头的代码命中。个人资料中的专业属于该范围时，相关文字和代码可计入专业初步匹配。
5. **自动判断哪些条件？** 可明确读出的专业、学历、政治面貌、基层年限和明确“不限 / 无要求”等条件；“与最高学历相对应的学位”按符合处理。应届、服务项目和非标准备注只在依据充分时判定，否则待核验。
6. **哪些需人工确认？** 无法与个人专业对应的相关 / 相近专业及专业目录归属、毕业身份政策、服务基层项目口径、备注条件、预备党员等政治面貌边界，以及职位表未明确的条件。专业已初步匹配、资料完整且无明确不符合时，综合状态显示初步符合；其余待核验细节仍保留在职位详情中。
7. **筛选条件？** 关键词、专业原文及公共管理专业快捷筛选、工作省市区、招录部门、机关类型、学历 / 学位 / 政治面貌 / 基层年限 / 考试类别、面试专业测试、备注 / 项目条件、招录人数范围、资格状态、排除仅限男性岗位及其他排除开关、排序。
8. **筛选能否保存恢复？** 能。筛选方案、当前条件、收藏、比较和岗位备注写入现有档案，并进入既有加密备份 / 手动同步路径。
9. **国考比较是否独立？** 是。只接受 `national:2027:` 标识，最多 6 个国考职位；京考比较结构未合并。
10. **学习系统是否共用？** 是，沿用原学习计划、行测、申论和模考页面及同一份学习记录。
11. **测试情况？** 本次完整 `npm test` 通过，101/101；国考 Python 导入测试 4/4、校验器测试 2/2；生产构建和国考源表逐条校验通过。既有 `npm run data:check` 的结构检查通过；它继续报告原有北京历史职位覆盖未达到全量，原因是年度官方职位分母未核实。
12. **本地如何启动？** `npm run build` 后运行 `python3 -m http.server 4172 --directory dist --bind 127.0.0.1`，浏览 `http://127.0.0.1:4172/`；或使用 `npm run dev` / `./start.sh`。
13. **如何更新 GitHub Pages？** 提交并推送到仓库默认分支会触发既有发布工作流；工作流测试、构建 `dist/` 并部署。
14. **如何导入更新职位表？** 安装 `scripts/national/requirements.txt`，运行 `npm run national:import -- --source <2027-xls>` 生成职位 JSON、元数据和审计，再运行 `npm run national:check -- --source <2027-xls>`。新版年份需先扩展导入器 / 加载路径和测试。
15. **尚未完成项？** 没有报名、资格审查、竞争比或进面分数据；官方附件字节比对和浏览器手工视觉回归未完成。专业原文搜索不是完整专业目录索引。CSV 是 Excel 可读 CSV，不是 XLSX；复杂资格规则需人工判断。
