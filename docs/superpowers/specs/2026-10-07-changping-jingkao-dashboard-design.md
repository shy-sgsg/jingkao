# 北京京考 · 昌平选岗与50天备考决策系统

## 设计规格（2026-10-07）

### 目标与边界

建立一个可在本机运行、便于持续更新的个人京考决策网站。它把昌平区历年职位、公开竞争信息、可追溯的进面分数，以及现有50天学习计划和模考记录放在同一工作台，帮助使用者检查报考资格、比较历史相似职位、安排学习重点。

网站不是录取概率预测器，也不是官方招录信息的替代品。只根据已记录的来源与用户输入展示事实、差值、样本覆盖和带解释的排序。截至2026-10-07，官方招考目录未检出2027年度常规考试录用公告/职位表；这是目录检索状态，不代表官方已公布后续安排。不得展示预测职位。官方招考索引中已出现的2027定向选调和“优培计划”公告是另一招录项目，不视为普通京考职位表。

### 技术与运行方式

- 前端：React、Vite、TypeScript、Tailwind CSS、Recharts；本地静态单页应用，不设后端、不引入 SQLite。
- 数据转换：Python 与 openpyxl。ETL读取原始Excel副本和项目内的岗位/来源表，将校验后的数据输出到前端可读的JSON。
- 个人数据：报考条件、完成状态、模考记录、收藏与对比列表保存在浏览器 localStorage；不上传，也不回写原始Excel。
- 运行入口：项目根目录提供 start.sh 和 README；数据更新通过 scripts/rebuild_data.sh 完成，前端开发与生产构建分别使用 npm scripts。
- 原始文件：复制用户指定工作簿到 data/raw/，只读处理；保留原文件不变。更新工作簿后重新运行ETL，网站数据从表格重建。

### 信息架构

主导航采用适合日常使用的侧栏，默认进入首页。页面包括：

1. 首页：计划进度、今日任务、行测/申论掌握情况、最近模考与波动、到目标分差值、历史同类岗位关注项、未来七天薄弱项建议。
2. 50天计划：Day 1–50，按日期、阶段、任务、计划/实际题量和用时、状态及完成度查看；提供日历/时间轴和阶段视图。
3. 行测能力：七个能力模块及子模块；分别呈现训练完成度、正确率和掌握度。
4. 申论能力：训练次数、任务完成、关键词覆盖、自评分与能力掌握，不把单一分数当作客观测量。
5. 模考分析：行测/申论/总分走势，130/135/138/140目标线，模块表现，最近3/5套均值与标准差，基于记录计算的薄弱项和未来七天建议。
6. 昌平职位库：按年度、区直/街道/镇、单位、岗位类型、专业、学历、招录数、身份限制、体测、竞争数据、进面线等搜索、筛选、排序和收藏；行展开详情。
7. 岗位详情与比较：展示职位条件、带时间戳的竞争观察、可比历史分数、同单位/同类岗位、个人资格判断和分数安全垫；最多比较5个岗位。
8. 选岗助手：先做硬性资格检查，再按分数、历史竞争、招录数、限制优势和个人偏好进行可解释软排序；明确给出理由与待核项。
9. 分数情景：120–150分滑块，按实际收录的历史可比进面线展示低于/接近/高于的分数位置及样本覆盖数。若样本不完整，只称“收录样本覆盖”，不称全部职位覆盖或进面概率。
10. 昌平竞争矩阵：以区直、街道、镇及具体单位/街镇的矩阵展示岗位数、招录数、已有竞争观察和分数样本；不使用缺少可靠行政边界依据的地图。
11. 数据与来源：可按岗位或字段查看原始URL、发布/抓取时间、来源等级、证据类型、原值、口径和冲突说明。

### 数据模型与口径

岗位事实与报名/成绩观察分开存储，来源证据独立成表。至少提供 positions、observations、sources、study_plan 四类数据；处理后的JSON使用稳定ID互相引用。

职位表包含招考年度、职位代码、单位/用人部门、职位名称/类别、区直/街道/镇归属、职责、招录数、学历学位、专业类别与详情、应届、户籍/生源、政治面貌、基层经历、证书、性别/年龄、退役身份、体测/专业考试、面试比例、备注、可比组和字段来源。只有职位表实际记录过的单位才进入数据库；不得根据行政区划名录补造职位。

竞争观察至少分开记录 applicants_registered、applicants_qualified、applicants_paid、applicants_confirmed、actual_test_takers、recruit_count，并保留观察时间、来源口径和岗位代码。没有证据的值为 null，不为0。只有资格审查通过人数时，指标名为 qualified_competition_ratio = applicants_qualified / recruit_count。来源只写“报名/报录比”且分子口径未明时使用 unknown_registration_ratio，不混入已知口径数据。职位年度用招考公告年度标识，避免把报名或考试发生的日历年误作职位年度。

进面最低/最高/平均分、进入面试人数、拟录用综合成绩分开记录。笔试合格线与实际岗位进面分绝不合并。只有职责、学历、专业与关键身份限制足够接近的记录才进入 comparable_position_group；同单位或同岗位名本身不足以证明可比。

来源表包含 source_id、年度、职位代码、字段名/值、来源标题与URL、发布/访问时间、发布方、official/secondary/estimated等级、证据类型、可信等级和说明。估算值不得标作官方事实；同字段冲突保留多条来源证据并在展示层显式提示。

### 资格和评分行为

- 个人专业按用户目前提供的“公共管理专业”预置；学历、应届身份、政治面貌、户籍/生源、基层经历、证书、退役身份等一律由用户填写，不作推断。
- 硬筛选结果只有“符合”“不符合”“待补充”“待人工核验”。岗位文本缺失、专业代码映射不确定或个人信息为空，不会被默认当作符合。
- Job Difficulty Score 参考用户给定权重：历史进面线30%、资格审核竞争度25%、招录数15%、岗位限制宽窄15%、年度内稳定性10%、数据可信度5%。跨年分数使用年度内相对位置；样本不足时不造分位数。核心分量缺失或样本不足时隐藏总分，展示可得分项和覆盖情况。
- Fit Score 先要求硬筛通过，再参考竞争难度30%、历史进面安全垫25%、招录人数15%、稀缺限制优势10%、岗位类型偏好10%、地点偏好5%、证据可信度5%。输出排序必须附逐项理由；资料不足时不给伪精确总分。
- 安全垫定义为最近5套有效模考均分减去选定的、年度匹配且可比的历史进面线。样本太少时显示原始差值及样本数，不硬套风险等级；不显示“上岸概率”。情景模拟的覆盖值限定为当前筛选条件下已收录的历史分数样本，并显著显示分母与完整性。
- “未来7天建议”基于最近有效的模块正确率、计划完成、模考分数与波动计算；缺少有效记录则解释数据不足，不输出固定建议。

### 界面方向

采用桌面优先、移动端可浏览的中文界面：深蓝/靛青作为主色，青绿作正向状态，橙黄作提醒，红色仅用于高风险。卡片边界克制、留白充足、重要数字突出；宽表格在容器内滚动，图表使用清晰单位和一致尺度。使用系统中文字体栈，不依赖远程字体。视觉参考“个人决策工作台”，避免营销首页或后台管理表格观感。

### 交付与验收

项目交付研究报告、研究方法、Excel评审、来源审计、数据质量报告、最终摘要；提供职位/来源数据、转换脚本、校验脚本、前端源码、README和一键启动脚本。校验至少覆盖职位代码重复、招录数异常、字段口径错配、空值被写为0、来源缺失、年度/职位错配、竞争比计算及来源冲突。

完成后按用户要求实际执行 npm install 与 npm run build，启动网站检查桌面及移动布局，重点验证首页、筛选/排序、职位详情、对比、资格判断、情景模拟、模考图和50天计划；记录实际执行结果。原始Excel内容与字节应保持未改动；网站中的空值、来源和口径均可检查。

### 分阶段执行

1. 按官方优先级补齐职位原始表与来源证据，整理2024–2026记录，核对同名职位和年度口径，并形成方法、发现、Excel评审与质量报告。
2. 实现可重建的数据层、校验脚本和用户提供的工作簿导入。
3. 实现本地SPA、各页面交互和透明模型。
4. 安装依赖、构建、启动并按验收重点进行实机/浏览器检查，修复发现的问题。
