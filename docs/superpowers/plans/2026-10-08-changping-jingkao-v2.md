# 昌平京考备考与选岗网站 V2 实施计划

> **执行方式：**按用户要求由当前实现者连续执行；任务按阶段可独立验收。代码改动使用 TDD；不做 Git 提交（当前目录不是 Git 仓库）。

**目标：**把现有网站升级为可读、可解释、尽可能完整且源证据可追溯的昌平京考备考与选岗工具，并如实呈现尚未取得的数据。

**架构：**保留现有零运行依赖静态 SPA 与 Python/openpyxl ETL。先补齐来源证据和规范化职位/观察数据，再让职位库、资格筛选、历史分数情景、选岗安全垫及研究页面消费同一数据合同；个人状态继续只留在浏览器 `localStorage`。

**技术栈：**原生 JavaScript/CSS、Python/openpyxl、Node test runner、浏览器 `localStorage`；不为视觉效果迁框架或新增运行依赖。

**依据：**用户提供的 `/home/shy/.codex/attachments/7570a630-1f87-4272-993b-d0531d1dc808/pasted-text-1.txt` 与现有 `docs/superpowers/specs/2026-10-07-changping-jingkao-dashboard-design.md`。新任务文件的范围优先于旧计划。

## 全局约束

- 原始 `/home/shy/jia/考公/北京京考50天复习计划_昌平街道导向_自检版.xlsx` 绝不覆盖或写入。
- 所有缺失数值保持 `null`；不推算不存在的报名、进面或录取概率。
- 区分报名、资格审查通过、缴费、确认参考和实考口径；区级/单位级数据不下放为岗位事实。
- 2027 定向选调/优培不等于普通京考；状态按最新官方目录和查询日期表达。
- 官方、交叉一致二手、单一二手和待核验记录分别标注；镜像一致不伪装成官方核验。
- 个人报考资料、训练日志和模考只保存在本机 `localStorage`，不发送到外部服务。
- 使用系统中文字体与本地资源，不加载 CDN；保留减少动态效果支持。
- 沿用当前 SPA/ETL，不执行旧计划中的 React/Vite/Tailwind 迁移。
- 浏览器预览只经本机 HTTP；不得用 `file://` 或未经授权的外部发布规避本机限制。

## 审阅重点

- 官方附件与镜像的职位代码集合不一致时：验证差集、统计范围和职位年度，禁止用总量倒推缺失记录。
- 专业代码或资格原文不完整、学历层级/学位未知时：状态保持待核或条件待核，不默认可报。
- 同一岗位多时点资格审查人数变化时：保留每个时点，不将过程快照混成最终报名竞争比。
- 同名岗位存在多个代码或多条进面分时：仅唯一匹配才标 `high`，其余保持 `ambiguous`/`unmatched`。
- 空模考、少于 5 套模考、过滤后零样本和跨年度比较：不以 0 替代缺失，不给伪稳定性或录取概率。

## 计划自审

- **规格覆盖：**用户条目 1–5 的字体和密度归阶段 2；6–10 的引导、快速开始和页面帮助归阶段 2/6；11–20 的职位、来源、字段与资格分类归阶段 3/4；21–27 的分数行、覆盖率和年度情景归阶段 5；28–42 的双阶段决策、报名口径和数据仪表盘归阶段 4–6；43–80 的首页、诊断、详情、比较、专题与表格交互归阶段 5–6；81–99 的架构边界、原始证据、审计、报告、测试与交付归阶段 1–7。无证据的数据保留为缺口而非删项或造数。
- **步骤粒度：**每个实现子任务以独立失败行为测试开端；数据收集与页面实现分阶段可验证。
- **接口一致性：**职位、观察、来源仍按当前 Python ETL 输出到 `public/data.json`；前端消费相同字段；变更模型时先扩展 ETL 与验证测试。
- **Review Focus：**五类边界分别绑定到职位差集、资格匹配、时序报名、分数映射、安全垫/空样本测试。
- **比例：**计划列出必要阶段而不重复粘贴需求或设计代码；用户的实际网站、数据、研究与浏览器验收仍为最终产物。
