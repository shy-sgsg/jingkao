# 数据与分析口径

版本日期：2026-10-07。本文为项目计算口径；官方规则或数据结构变化时，按年度保存口径版本，不覆盖历史解释。

## 1. 职位数据与专业匹配

- 历史职位记录的一行粒度为“一个年度的一条正式职位代码”。主键候选为 `exam_year + position_code`；职位名称相同不能作为唯一键。
- 招录人数是计划数；职位数、招录人数、资格审核通过人数、缴费人数、实际参考人数分别存储，不互相代替。
- 仅从公告/职位表字段建立职位条件；保存原始文本、规范化字段、来源 URL、抓取时间、官方/二手级别、核验状态。
- 用户已提供的专业方向为公共管理；这不足以推断学历层次、具体专业代码、应届身份、户籍、基层经历、政治面貌、资格证或职位定向资格。上述条件在用户填写前一律为“未评估”。
- 匹配结果分为“明确匹配”“明确不符”“需人工确认”“用户信息不足”。专业代码匹配要区分学术学位专业目录（例如 1204）与专业学位类别（例如 1252），不可只对“公共管理”四个字做模糊匹配后宣称符合资格。
- 不根据未输入的身份、性别、年龄、户籍或资格作推断；存在具体职位备注时，将原文展示并提示向招录单位核实。

## 2. 报名竞争数据

- 每条人数统计带 `exam_year`、`position_code`/汇总范围、`metric_type`、`as_of` 时间、`numerator`、`recruitment_count`、来源及状态。
- 若来源确实提供同一时点、同一范围的资格审核通过人数，则展示“截至该时点过审人数/计划招录数”；不得叫作录取概率，也不能与最终实考人数混用。
- 区级“平均竞争比”只有在来源披露职位级样本、平均定义、时间点和分母时才可解释；平均比值通常不可乘回招录数来得到全区总报名数。
- 缺报名数据时显示“暂无可靠职位级数据”；不插补 0、不用其他区县平均、不把“无人过审”作为最终报名结果。

## 3. 分数与进面边界

- 分类笔试合格线、职位最低进面分、入围考生分数、最终综合成绩是四种不同概念，独立字段、独立标签。
- 当前可确认的官方 2026 数据是按职位类别划分的资格线；官方公告说明普通职位行测/申论各占笔试成绩 50%，公安人民警察职位为行测 40%、申论 30%、专业科目 30%。这些是 2026 规则，仅作年度历史解释；2027 需等待新公告和考试大纲。
- 官方面试名单如果只列人名/报名序号/职位代码/时间，不从名单反推职位分数线。二手分数样本只能以“部分样本/第三方整理”展示并带样本数、区间和链接。
- 未取得同职位、同分数口径、可复核来源的 cutoff 时，相关分值为 `null`；不以全区平均分、资格线、计划招录数推算单职位 cutoff。
- 不输出“上岸概率/进面概率”。可输出可解释的学习记录、职位条件匹配、历史公开样本差距；任何合成 readiness 分须冠以“自我跟踪指数（非概率）”，并公布公式和输入完整度。

## 4. 学习记录与缺失值

- 原工作簿计划值、用户实际记录、外部招考数据分层存放。
- 空白、未参加、未统计、来源未公布一律作为 `null` / 未观测；数值 0 只表示用户或来源明确记录为零。
- 正确率仅在实际作答题量大于 0 时计算；有效模考场次为 0 时均分、分差和 readiness 不可用；少于 2 场时标准差/稳定性不可用。
- 清单 mastery 若以计划题量和正确率复合，应同时展示覆盖度；未练习项目标记“未开始/未测量”，不显示为能力零分。
- 计划完成率以截止日之前有明确完成记录的计划项作分母；空白日不默认视为完成或未完成。用户可以选择是否把“漏记”视为未完成。
- 按工作簿目标保存的 50 天安排为计划意图（5,520 题、341 小时），不宣称用户已经投入这些时间，也不据此评价计划合理性。

## 5. 汇总统计与可视化

- 职位竞争/分数分布先按年份、职位类别和来源状态筛选，再展示样本数 `n`、中位数、四分位数和极值；当来源是部分样本，图表标题和图例明确标“非全量”。
- 2024–2026 招录汇总来源口径目前不一致；在岗位代码级 reconciliation 前，不将它们绘成连续趋势线，也不在正文给出确定的同比结论。
- 公共管理职位筛选应可复现：展示匹配的是原始专业要求中的哪段文本/代码，模糊或需人工确认字段不纳入“明确符合”计数。
- 雷达/分项能力图只用用户实际录入且有足够样本的数据；不可用项目显示缺失，不补零。

## 6. 质量闸门

对导入数据至少检查：职位代码主键重复；招录人数为正数；年份/日期解析合法；表头及关键字段映射完整；岗位总数与计划人数按来源复算；单位和区县归属一致；报名统计的时点/类型未混淆；分数口径及上限一致；每条二手记录有 URL、抓取时间、来源标签及对账状态。出现冲突时保留来源级原值及冲突记录，禁止静默覆盖。
